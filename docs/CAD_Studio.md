## 1. 탐색 및 문서 운영

- **읽는 순서:** 프로젝트 목적 → 요구사항 → 시스템 아키텍처 → 기능별 설계 → 개발 로드맵 → 스프린트·단계별 태스크 → 기술 학습·검증.
- **구현 변경 시:** 관련 설계 문서, 해당 단계 태스크, 테스트·검증 산출물을 함께 갱신합니다.
- **아카이브:** 과거 기획은 참고용입니다. 최신 사양을 확인할 때는 `종합_기획_문서/`를 우선합니다.
- **링크 방식:** 고유한 문서는 제목 기반 위키 링크를 사용하고, 이름이 중복되는 문서는 폴더 경로를 포함해 링크 충돌을 방지합니다.
- **Obsidian:** 본 폴더를 Vault로 열거나 기존 Vault에 폴더째 넣으면 내부 위키 링크로 탐색할 수 있습니다.

## 4. 문서 관계와 갱신 규칙

- **기획 변경:** 프로젝트 목적·요구사항과 해당 종합 기획 문서를 먼저 갱신합니다.
- **구현·아키텍처 변경:** 구조 설계와 기술 결정(ADR), 단계별 태스크를 함께 갱신합니다.
- **검증 기록:** PoC, 테스트 결과, 릴리즈 게이트는 `검증_산출물/`에 기록합니다.
- **재현성:** 기존 도면 포맷·API 계약에 영향이 있다면 호환성 및 롤백 문서를 같이 검토합니다.

> 최상위 진입점: **[[CAD_Studio]]** — 각 문서는 원래 폴더에 두고, 이 허브에서 연결합니다.

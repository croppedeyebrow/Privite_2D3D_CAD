# 개발 테스크 분할 계획

## 1. 테스크 운영 원칙

각 테스크는 작게 구현하고 다음 결과를 남긴다.

- 변경 목적
- 변경 파일
- 영향받는 crate
- 테스트 항목
- 승인 필요 여부
- 검증 결과

핵심 도메인 기능은 기능 구현과 테스트를 같은 테스크로 묶는다.

## 2. 단계별 테스크

### Phase 0: 프로젝트 기준 정리

- [ ] `docs/` 문서 체계 확정

- [ ] 현재 코드와 문서의 불일치 목록 작성
- [ ] CI 또는 로컬 검증 명령 정리
- [ ] 테스트 실행 기준 확정

완료 기준: 신규 AI 에이전트가 문서만 읽고 프로젝트 구조와 작업 규칙을 이해할 수 있다.

## 3. 테스크 완료 기준

- 컴파일 성공
- 관련 테스트 추가 및 통과
- `cargo fmt --all -- --check` 통과
- `cargo clippy --workspace --all-targets -- -D warnings` 통과
- 기존 동작 회귀 없음
- 저장 형식 영향 기록
- 사용자 승인 필요 여부 기록

## 4. 사용자 승인 필요 테스크

- 외부 의존성 추가
- 저장 schema 변경
- 기존 데이터 변환
- 파일 삭제·이동·덮어쓰기
- GUI framework 변경
- 렌더링 backend 변경
- 네트워크 또는 외부 API 사용
- 기존 테스트 제거

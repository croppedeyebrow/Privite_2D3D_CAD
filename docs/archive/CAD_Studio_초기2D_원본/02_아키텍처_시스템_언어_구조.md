# 아키텍처, 시스템 디자인 및 언어 사용 구조

## 1. 설계 목표

- UI와 CAD 엔진을 분리한다.
- 도면 변경을 command로 통일한다.
- GUI와 CLI가 동일한 엔진을 사용한다.
- 저장 형식과 내부 도메인 모델을 분리한다.
- 계산과 출력 결과를 deterministic하게 유지한다.
- 핵심 로직은 테스트 가능한 순수 Rust 코드로 유지한다.

## 2. 전체 시스템 구조

```text
┌────────────────────────────────────────────┐
│                  cad_app                    │
│       GUI, 입력, 패널, 도구 상태            │
└─────────────────────┬──────────────────────┘
                      │ UI 이벤트
┌─────────────────────▼──────────────────────┐
│                cad_command                  │
│       command 검증, 실행, undo, redo         │
└──────────────┬───────────────┬──────────────┘
               │               │
┌──────────────▼──────┐ ┌──────▼─────────────┐
│      cad_core       │ │  cad_geometry      │
│ 도면 모델, ID, 검증  │ │ 기하 계산, 스냅     │
└──────────────┬──────┘ └──────┬─────────────┘
               │               │
        ┌──────▼──────┐ ┌──────▼─────────────┐
        │ cad_render  │ │  cad_tolerance     │
        │ 렌더 모델    │ │ 공차와 계산 trace   │
        └──────┬──────┘ └────────────────────┘
               │
        ┌──────▼─────────────────────────────┐
        │ cad_io / cad_batch / cad_cli       │
        │ 저장, 출력, 자동화, 명령줄 실행      │
        └────────────────────────────────────┘
```

## 4. crate 책임

| crate | 책임 |
|---|---|
| `cad_core` | Project, Drawing, Entity, Layer, Dimension, Group, ID, validation |
| `cad_geometry` | 거리, 교차, 변환, 경계, 스냅, 근접점 |
| `cad_tolerance` | 공차 범위, 누적, 반올림, 계산 trace |
| `cad_command` | command 실행, 검증, undo/redo, replay |
| `cad_render` | 도메인 모델을 RenderPrimitive로 변환 |
| `cad_io` | 저장, 불러오기, 백업, 복구, 외부 출력 |
| `cad_batch` | 반복 작업과 대량 출력 |
| `cad_cli` | GUI 없는 검증, 출력, 복구 |
| `cad_app` | egui/eframe 기반 GUI |

## 5. 의존성 방향

허용 방향:

```text
cad_app -> cad_command -> cad_core
cad_app -> cad_render -> cad_core
cad_geometry -> cad_core
cad_tolerance -> cad_core
cad_cli -> cad_io -> cad_core
cad_batch -> cad_command / cad_io / cad_core
```

`cad_core`는 UI, 데이터베이스, 렌더링 backend에 의존하지 않는다.

## 6. 데이터 흐름

```text
사용자 입력
  -> UI 이벤트
  -> DrawingCommand 생성
  -> command 검증
  -> Core Model 변경
  -> 전체 모델 검증
  -> Render Model 갱신
  -> 화면 표시
  -> 자동 저장 예약
```

## 7. 언어 사용 구조

### Rust가 담당하는 영역

- 핵심 도메인 모델
- 기하 계산
- 공차 계산
- command와 undo/redo
- 검증
- 저장과 출력 pipeline
- CLI와 batch 처리
- GUI 애플리케이션

### 외부 포맷이 담당하는 영역

- JSON 또는 SQLite: 내부 프로젝트 저장
- SVG: 2D 검증 및 웹 호환 출력
- PDF: 인쇄와 배포
- DXF: CAD 교환
- DWG: 향후 별도 adapter 또는 SDK 검토

외부 포맷의 구조를 `cad_core`에 직접 넣지 않는다.

## 8. 데이터 모델 원칙

- 모든 영속 객체는 안정 ID를 갖는다.
- 내부 길이 단위는 밀리미터다.
- 화면 선택 상태와 렌더 캐시는 영속 모델과 분리한다.
- 내부 ID와 DXF/DWG handle을 분리한다.
- 파일 schema version과 애플리케이션 버전을 분리한다.
- 지원하지 않는 외부 객체는 가능하면 Unknown 형태로 보존한다.

## 9. 외부 의존성 정책

외부 crate 추가 전 다음을 검토한다.

- 유지보수 상태
- 라이선스
- 보안과 공급망 위험
- 빌드 재현성
- 성능 영향
- 저장 파일 호환성 영향

GUI, 렌더링, 저장 backend의 교체는 사용자 승인 대상이다.

# 03. 단계별 개발 WBS·의존성·완료 게이트

버전: v1.0. 기간을 임의로 보장하지 않습니다. **개인 개발을 위한 위험 제거 순서**이며 Phase 완료는 증거물에 의해 판정합니다.

## 0. 전체 계획의 변경점

기존 Phase 0~9는 기초 2D와 후반 DXF가 중심이었습니다. 새 계획에서는 **Kernel PoC와 FFI 안전성을 GUI 대규모 제작보다 먼저 검증**하고, R2 단일 3D 부품 완주를 최우선 납품 단위로 삼습니다. R3 이상은 R2 완료 후 결정합니다.

| Phase | 주제 | 핵심 선행 | 완료 산출물/게이트 |
|---|---|---|---|
| P00 | 현행 레포 인벤토리·기준 테스트 | 없음 | 기존 동작 고정, 스키마/테스트 맵 |
| P01 | 문서/ID/Units/Command v2 | P00 | 도메인 revision·transaction/rollback |
| P02 | **Kernel·FFI·STEP PoC (우선)** | P00 | OCCT/Truck 후보 보이는 증거와 ADR |
| P03 | 2D drafting/geometry/robust snap | P01 | 표준 fixture의 편집·SVG 출력 |
| P04 | Sketch Plane + constraints solver | P01,P02 | 닫힌 스케치/DOF 진단 |
| P05 | Feature DAG / 3D solid modeling | P02,P04 | Extrude/Revolve/Cut·변경 재계산 |
| P06 | 3D viewport / picking | P02,P05 부분 | 3D 조작·면/모서리 선택 |
| P07 | native v2 저장/재시작/복구 | P01,P05 | 비정상 종료/스키마 회귀 |
| P08 | STEP/STL + CLI 연계 | P02,P05,P07 | 독립 CAD 교차검증 |
| P09 | 통합 GUI / 단일 파트 E2E | P03~P08 | R2 출시 게이트 |
| P10 | 2D 도면 링크/정밀 출력 | P09 | R3 조건부 |
| P11 | 고급 Feature + PBR 렌더 | P09 | R3 조건부 |
| P12 | 건축/어셈블리·확장 | P10,P11 | 별도 범위 결정 |

## P00 — 기존 코드 기준 확보

- [ ] 실제 구현된 crate/API/커밋/테스트/GUI/저장 파일을 인벤토리화하고 문서 가정과 불일치를 기록.
- [ ] 데이터 포맷 fixture와 기존 2D 그림 goldens를 확정.
- [ ] Rust toolchain/MSRV, lockfile, Windows CI, 디버그/릴리스 빌드 방법 문서화.
- [ ] Crash recovery baseline and input path sandbox(절대/상대 경로, 경로 traversal) 테스트 확정.
- [ ] `cargo fmt`, `clippy`, `test`, supply-chain audit 명령을 로컬로 재현.
- **Exit:** 기존 파일을 열고 수정 후 저장하는 시나리오가 변경 없이 작동한다는 증거.

## P01 — Document v2 / Commands

- [ ] `DocumentId`, `SketchId`, `FeatureId`, `BodyId`, `ShapeRevisionId`, `MaterialId` 타입 정의.
- [ ] mm-based `Length`, radians `Angle`, `Transform3`, `Plane3`, unit conversion 정책.
- [ ] immutable revision / transaction staging / expected_revision 충돌 처리.
- [ ] geometry·layer·param update를 typed command로만 변경.
- [ ] Undo/Redo 재생/스냅샷 전략(메모리·디스크 정책) PoC.
- [ ] locked object/invalid parameter/unknown ref의 실패 시 rollback.
- **Exit:** 프로퍼티 기반 command run→undo→redo가 동일 domain state를 재현하고 실패 시 불변.

## P02 — 커널 선택을 위한 Spike (개발 초기에 반드시)

- [ ] Rust native 후보 Truck와 OCCT C++ 후보를 동일 입·출력/검증 API로 비교.
- [ ] Windows/MSVC 빌드, CMake/vcpkg/FFI/디버깅/배포 가능성 파악.
- [ ] Test A: 100×60×10 mm 판재, 중심 10 mm 관통홀 → shape validity/volume/BBox 확인.
- [ ] Test B: Extrude→Boolean cut→Fillet를 반복 수행, 오류·예외·정밀도 측정.
- [ ] Test C: STEP 쓰기→외부 도구 열기→기하 비교→재수입.
- [ ] Test D: 최종면 참조 후 upstream 치수 수정→참조 유지/모호성 진단 테스트.
- [ ] C++ DLL license notices, attribution, relinking obligations 포함 배포 PoC.
- **Exit:** `10_ADR`의 선택 기준에 따라 primary kernel 결정; 부족한 기능은 release 범위에서 제외.

## P03 — 2D Drafting (R1)

- [ ] 선/호/원/폴리라인/텍스트의 distance/intersection/validity.
- [ ] 이중 좌표 변환 `screen→sheet/model plane→document`, 줌 종속 snap tolerance.
- [ ] layer visibility/locking/draw order/edit state.
- [ ] 치수 값, 공차 trace, 동일 도면 PDF/SVG(해당 release 시점 지원만).
- [ ] Selection broad-phase index + precise hit-test; 다중 선택/속성 편집.
- **Exit:** 예시 도면 10개에서 수치 입력/편집/저장/검증/출력 회귀 통과.

## P04 — Sketch / Solver

- [ ] Sketch는 Plane2D-local XY로 계산, World transform으로 3D에 부착.
- [ ] coincident/parallel/perpendicular/horizontal/vertical/distance/radius/angle(지원되는 것만 UI 노출).
- [ ] DOF 상태: under/fully/redundant/conflicting/unsolved 식별.
- [ ] solver 수렴 제어(max iterations/timeout/tolerances), 결과 trace, 에러 원인 ID.
- [ ] 폐합된 wire/region 검증(스케치 방향/홀 포함, 중첩·자가교차).
- **Exit:** 완전 구속 사각형 및 동심 원 프로파일 테스트, 숫자 치수 수정 재계산 안정.

## P05 — 3D Feature/Recompute

- [ ] Feature DAG topo-sort, cycle reject, dirty descendant invalidation.
- [ ] Sketch-based Extrude/Revolve & Boolean Fuse/Cut/Common 중 검증된 subset.
- [ ] Body/Solid/Shell/Face/Edge/Vertex의 API-level 계층, shape validity check.
- [ ] upstream change → recompute staging → commit/rollback.
- [ ] topology ref persistence, ambiguity/lost reference indicator; feature history if supported.
- [ ] geometry cache key `(document revision, feature id, params, kernel version, tolerance config)`.
- **Exit:** 5종 기준 파트 생산 + 치수 변경 후 형상·피처 이력의 안정성 확보.

## P06 — 3D 화면

- [ ] kernel B-Rep tessellation(vertex, triangle, normal, face id mapping).
- [ ] wgpu viewport D3D12/Vulkan adapter probe, fallback/reporting.
- [ ] orthographic/perspective, orbit/pan/zoom/fit, axis triad/grid.
- [ ] selection: body/face/edge, hover highlight, gizmo, clip/section(P1).
- [ ] GPU resource cache incremental update; stale result discard.
- **Exit:** 부품 회전 중 모델의 도메인 revision 불변, Face selection 후 정확한 Feature 컨텍스트 표시.

## P07 — 저장/복구

- [ ] native archive manifest/schema/feature graph/sketch/geometry storage.
- [ ] 모델·캐시 분리; 캐시 없는 파일 load 테스트.
- [ ] atomic save/backups/autosave/validation/checksums/temp file protection.
- [ ] v1 2D→v2 migration/읽기 전용 롤백 정책.
- [ ] corrupt/truncated/unsupported version/oversized input handling.
- **Exit:** 단계별 저장 실패주입+강제 종료 테스트 후 recovery 절차 확인.

## P08 — 교환 및 자동화

- [ ] STEP ACIS가 아닌 OCCT의 STEP adapter 검증(선택 kernel 기준).
- [ ] STL triangulation/volume/unit/gap checks.
- [ ] SVG export와 CLI validate/inspect/export/recover 공통 서비스 연결.
- [ ] glTF PBR scene export는 R3 진입 시 구현.
- [ ] 포맷 손실 설명(imported STEP에는 원본 feature tree 미복원 등).
- **Exit:** 외부 CAD tool 왕복 형상 비교 fixture 보유.

## P09 — 사용자 E2E 통합

- [ ] Sketch Editor/Feature Tree/Properties/3D View/Issue panel 연결.
- [ ] 피처 오류 → 카메라/트리 위치 이동, 명확한 복구/취소.
- [ ] Keyboard command, numeric input, focus rules, save-recovery UX.
- [ ] Standalone installer/portable Windows package with license notices.
- **Exit:** README 8-step R2 시나리오 UI 기준으로 독립 사용자 재현.

## P10~P12 — 후속(조건부)

- **P10:** model-linked orthographic drawing, hidden-line removal, sheets, PDF, dimensions, DXF adapter 선택.
- **P11:** fillet/chamfer, edge remapping, pattern/mirror, PBR materials/lights, PNG, glTF.
- **P12:** assembly reference model, interference, 3D PMI, architectural workbench with own data semantics/IFC.

## 4. 완료 정의(각 Task 공통 DoD)

1. 요구사항 ID와 설계 결정, 변경 crate 및 영향되는 파일 schema가 명시됨.
2. 정상+예외 unit/integration/E2E test 기록.
3. `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`, `cargo test --workspace` (실제 네이티브 종속 환경 적합성 별도 체크).
4. 신규 배포 라이브러리의 법적·보안 검토/버전 pin/SBOM 완료.
5. 변경이 저장/Undo/모델 validity/렌더 성능에 미치는 영향 측정.
6. 실패 시 데이터 손상/크래시로 이어지지 않는지 반례 시험.
7. UI 실행 가능한 사용자 워크플로 또는 CLI contract로 검증.

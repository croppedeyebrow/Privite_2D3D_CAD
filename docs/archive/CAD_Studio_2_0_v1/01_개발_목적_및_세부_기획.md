# 01. 개발 목적 및 기능 요구사항 명세

버전: v1.0 | 요구사항 표기: FR / AC | 출처 구분: 기존 2D 목적 확장 + 신규 3D 기획

## 1. 핵심 사용자 스토리

**US-01 부품 제작:** 사용자가 스케치를 치수로 정의하고 Extrude/Cut을 적용하여 STEP/STL로 전달합니다. 설계 치수를 바꾸면 모델이 재생성됩니다.

**US-02 기계 도면:** 사용자가 mm 단위의 선·원·호·폴리라인과 치수·공차를 작성하고 용지 크기/축척을 지정해 검증 후 SVG/PDF로 출력합니다.

**US-03 재사용:** 사용자가 모델의 치수 파라미터를 바꾸어 가족 부품을 일괄 생성하고, 오류가 난 항목만 따로 보고받습니다.

**US-04 3D 설계 검토:** 사용자가 솔리드를 선택하고 면·모서리·부피·바운딩박스·단면을 검토하며 원하는 카메라 구도로 이미지 출력합니다.

**US-05 데이터 복구:** 편집·저장 중 종료되었을 때 사용자 승인을 받아 복구 사본을 열고, 정상 파일은 손상하지 않습니다.

**US-06 건축 2D:** 사용자가 벽 중심선/외곽, 창호 기호, 치수, 층 구분 레이어를 사용한 건축 평면을 작성합니다(의미적 BIM은 후속 범위).

## 3. 주요 업무 흐름과 예외

### WF-A: 2D 스케치 기반 3D 파트

1. New Part → 문서/단위 선택 → Sketch Plane 지정.
2. 선·사각형·원 작성 → 스냅 → 치수·기하 구속 → 구속 상태 배지 확인.
3. 닫힌 프로파일 선택 → Extrude 입력(방향/거리/합집합 또는 새 Body).
4. Feature DAG에 노드 추가 → solver/geometry/kernel 검사 → shape commit.
5. Face 선택 → 스케치 추가(대상 참조는 topology naming 정책 사용) → Cut.
6. 치수 수정 → 해당 피처부터 dirty 표시 → background recompute → 성공 시 shape revision 갱신.
7. STEP/STL export 전 shape validity 및 단위 검사; 오류는 차단하거나 명시 경고.

**예외 AC:** Zero-length edge, self-intersecting wire, non-manifold, tangential boolean, lost face ref, kernel timeout/crash는 모두 문서와 기존 결과의 무결성을 해치지 않아야 합니다.

### WF-B: Drawing 생산

Draft Entity → Layer/LineStyle → Dimension/Tolerance → Sheet/Layout → 검증 → SVG/PDF. 3D 모델 연계 투상도는 P1에서 독립 DrawingView 타입으로 구현하며 스케치 entity를 그대로 투상도로 오용하지 않습니다.

### WF-C: 저장 실패

현재 정상 파일을 변경하지 않은 상태에서 snapshot/validation→temporary write→flush→read-back→replace→backup rotation. 단계별 실패에서 원본/새 autosave/백업 중 복구 가능성을 반드시 확인합니다. 운영체제와 파일 시스템의 atomic semantics가 다르므로 강제 중단 테스트를 기준으로 함.

## 4. 책임/검증 추적

- 모든 FR은 `Feature ID`, 담당 crate, Command API, Storage Schema 영향, Unit Test, E2E fixture, 에러 코드, 릴리즈 게이트에 연결합니다.
- **P0와 P1을 혼합하여 완성을 주장하지 않습니다.** P0는 단일 부품 설계·재편집·안전 저장의 end-to-end에 집중합니다.
- 성공 기능뿐 아니라 예상 실패(geometry, serialization, GPU, FFI)를 테스트 자산으로 유지합니다.
